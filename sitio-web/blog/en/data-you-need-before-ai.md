Every week we talk to companies that want to "use AI". Some picture an assistant that answers questions about sales; others, a system that enters orders by itself or anticipates demand. All of those ideas are possible today, and they have one thing in common: **artificial intelligence is only as good as the data it consumes**.

An agent connected to messy data does not get smarter: it gets things wrong faster and more confidently. So before choosing a model or a tool, it pays to look at the data.

## 1. Knowing where each piece of data lives

The first step is an inventory. Where are sales, stock, customers, prices, targets? In most companies the answer includes an ERP, a CRM, several Excel files, exports from distributors and, more and more, orders and questions arriving over WhatsApp or email.

Not everything has to be in one system, but you do need to know **which source is the official one for each piece of data**. If the month's sales are one number in the ERP and another in the sales team's spreadsheet, an AI agent will not know which to use.

## 2. One record per customer, product and supplier

Duplicates are the most common problem and the most damaging. The same customer entered as "Northern Supermarket Ltd", "Northern Supermarket" and "NORTHERN SUPERM." becomes three different customers for any analysis.

When you ask an agent "how much did this customer buy from us this year?", the answer will be wrong if the records are not unified. Deduplicating and assigning unique codes is work you do beforehand, but it is what makes the answers trustworthy.

## 3. Common criteria

Units, currencies, dates and categories have to mean the same thing across every source. A few examples we see often:

- One system records sales in units and another in cases.
- One spreadsheet is in local currency and another in dollars, with no exchange rate noted.
- Product categories changed halfway through the year and the history carries both versions.
- Each department defines "active customer" differently.

Normalizing and documenting these criteria is what lets an agent compare and add up information from different sources without mixing apples and oranges.

## 4. Data that refreshes automatically

An agent answering with month-old data is no use for deciding. If today someone updates a report by copying and pasting every Monday, the AI will inherit that delay and those errors.

Before thinking about the agent, it pays to automate the data load: scheduled connections to each system, automatic pickup of distributor files, and checks that raise the alarm when something did not arrive or arrived with errors.

## 5. Permissions and traceability

Once the data is available to an agent, important questions appear: can everyone see everything? should one rep be able to query another's book? how does whoever receives an answer know where the number came from?

A good AI project defines from the start **what each user can see** and makes every answer cite its source. That builds trust and makes errors easier to spot.

## What if my data does not meet all this?

That is the normal case, and it is not a reason to postpone the project. It is the reason to start in the right place. Rather than trying to put all the company's data in order at once, we recommend:

1. **Pick one concrete use case** with clear impact — questions about sales for the commercial team, say.
2. **Prepare only the data that case needs**: the sources, the criteria and the checks.
3. **Run a pilot** with a few users, measure and adjust.
4. **Scale** to other cases, reusing what is already in order.

That way each step leaves more reliable data for the next, and the company sees results from the first project.

## In short

Before implementing artificial intelligence, check whether you can answer these five questions:

- Do I know where each piece of data lives and which source is official?
- Do I have a single record per customer, product and supplier?
- Do the different sources use the same criteria?
- Does the data refresh on its own?
- Is it defined who can see what?

If any answer is "no" or "I don't know", the first step is not choosing an AI model: it is preparing the data.
